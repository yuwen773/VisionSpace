# 生产部署契约：监听面、模型端点、模板与生产库

状态：已接受（2026-11-26，随 1.1.0 生产就绪 WP-01 生效）。

实机验收（M4，2026-11-25，阿里云 `121.199.77.168`）证明：迁移本体可以在 1.7 GB 机型上稳定跑起来，但**部署面**还留着一类「装得上、起来之后才出事」的缺口。本 ADR 把这些缺口写成长期契约，让它们不再依赖某一份散文手册。

## 1. 业务端口只绑回环

- `prod` profile 下 `server.address` 默认 `127.0.0.1`。公网入口只有 nginx 的 80/443，业务端口与 PostgreSQL(5432)、Redis(6379)、管理端口(9081) 一律不直接对外。
- 容器部署是唯一例外：`docker-compose.yml` 显式设置 `SERVER_ADDRESS=0.0.0.0`——容器内必须监听所有接口才能被 docker 端口映射；宿主机侧仍然只发布到 `127.0.0.1`（`ports: "127.0.0.1:${BACKEND_PORT}:8081"`）。
- 管理端口固定 `127.0.0.1:9081`，与业务端口分离。
- 纵深防御不能只靠安全组：安全组是外层，进程本身也要不监听非回环地址。

## 2. 模型端点与模型名不许为空

- `spring.ai.openai.base-url` 与 `spring.ai.openai.chat.options.model` 纳入生产守卫的必填清单。
- prod 配置里这两个属性**有可达的默认值**（`application-prod.yml`：`https://dashscope.aliyuncs.com/compatible-mode/v1` + `qwen-plus`），所以「完全没配」不会发生。守卫要挡的是**显式置空**：环境变量存在却是空串，属性被覆盖成空，请求会打向空地址。
- 原因（2026-11-25 实测）：在默认值落地之前，缺 `base-url` 时 OpenAI 客户端默认打 `api.openai.com`，大陆不可达，Agent 的同步调用挂到超时、SSE 一个字节都回不来。故障点在**首帧之后**，启动期完全看不出来。
- 报错把「缺」（missing）与「空」（blank）分开：前者是「加一个变量」，后者是「把值填上」，处置方式不同。
- 换供应商时两个键一起改；只加超时不算解决（超时只是让「首帧前的失败」不再被掐断，首帧延迟的根因另行定位）。

## 3. 部署模板属于仓库，且与代码一致性由门禁保证

- 原生部署的模板集中在 `deploy/`：环境变量、systemd 单元、nginx 站点、PG 参数、初始化与自检脚本。
- `scripts/tests/test-deploy-templates.py` 在每次验收与 CI 里校验：
  - 生产守卫要求的每个键，必须同时出现在 `deploy/app.env.example` 与 `.env.example` 里；
  - compose 必须把同一批键传给 backend；
  - 模板里的键必须全部登记（多一个少一个都红），杜绝「改了模板忘了改对照表」；
  - 关键默认值（回环绑定、模型端点、SSE 超时兜底）必须落在 `application-prod.yml` 上。
- 散文形式的清单挡不住漂移：M4 的实机故障正是「手册的 `app.env` 少写两个键」造成的。

## 4. 生产库用独立空库，验收库保留备份

- 生产库单独建（默认 `vision_space_prod`），由 Flyway 从空库建起；**验收库不直接转正**。
- 初始化脚本只新建库，不 drop、不 truncate、不改任何既有库；目标库已存在时直接拒绝执行。
- 验收库在切换完成前一直保留，且切换前必须先做一次 `pg_dump -Fc` 备份并长期保留（它是验收期证据，也是回退锚点）。
- 清理验收库是独立授权的动作，不由部署脚本代劳。
- 建表入口永远只有 Flyway（ADR-0004 §1）；初始化脚本只建角色、建库、装扩展、写授权。

## 5. 未替换的占位符必须让启动失败

生产守卫除了缺失、空白、开发回退值、英文占位词表外，还拒绝**含尖括号的模板占位**（如 `<运行角色口令>`）。理由：模板里的占位说明是中文，不在英文词表里，光靠词表会放它过去，服务带着假口令起来，比直接启动失败更难查。

守卫的报错文案因此从「production secrets are not configured」改为「production configuration is not complete」——检查项里已经不只有秘密。

## 6. 后果

- 新增 prod profile 的部署方式时，必须同时更新 `deploy/` 模板与门禁登记；只改一处会被门禁拦下。
- 任何在生产暴露的新端口，都要在这里写明它绑在哪个地址上。
- 模型供应商更换时，改 `SPRING_AI_OPENAI_BASE_URL` 与 `SPRING_AI_OPENAI_CHAT_OPTIONS_MODEL` 两个键，不要只改一个。
